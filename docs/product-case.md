# AI万链产品设计与迭代

AI万链的产品目标，是让成年独居上班族回到家后拥有熟悉自己的交流伙伴，同时减轻生活安排与琐事带来的负担。项目由张万基发起，主导产品定义、交互方案、优先级和验收，结合 AI 编程工具完成原型集成。

## 用户体验如何拆解

| 居家时刻 | 用户想得到什么 | 产品设计方向 |
| --- | --- | --- |
| 回到家 | 有人接话，愿意听自己说今天的事 | 自然问候、连续对话与适度主动交流 |
| 休息或做家务 | 不必一直拿手机操作 | 叫名唤醒、语音交流和多终端入口 |
| 临时想到一件事 | 说完就能交托，不必重复登记 | 记忆保存、明确的任务参数与执行反馈 |
| 睡前与次日准备 | 少操心提醒和计划 | 闹钟、生活安排；后续扩展资料整理与次日递送 |
| 换一个设备交流 | 不用重新介绍自己或重复话题 | 统一中枢承载对话状态与长期记忆 |

早期访谈、竞品研究和问卷设计用于发现需求差异，原型体验用于验证具体交互。主动程度、付费意愿与持续使用价值，是后续家庭试用的重要观察项。

## 案例一 连续接话从哪里开始计时

**问题。** 每说一句话都要按键或重复叫名字，会打断交流。引入短时跟进窗口后，如果从文字回复完成开始倒计时，语音还没播完，留给用户接话的时间就可能已经很少。

**产品判断。** 接话窗口应符合用户听到的节奏。小月说完，才轮到用户继续说。

**推动实现。** 将免按键唤醒与连续接话分开设计；约 15 秒的跟进窗口从音箱实际播放结束后开始，围绕当前对话判断是否接续。

**验收。** 完成「叫小月发起第一轮 → 听完回答 → 不再叫名字直接继续」的两轮实机测试，用户确认两轮均接上、声音自然连贯。

这项设计展示了需求拆解、状态时序和真实体验验收之间的联系。

## 案例二 把声音的机械感拆成可比较的问题

**问题。** 用户认可某一段声音，但新生成的句子在音色、停顿、语速和结尾上仍可能不一致。手机自然、音箱不自然时，问题也可能来自传输与播放。

**产品判断。** 目标是任意新回复都保持自然交流，而不是积累固定台词。音色、韵律、生成方式与终端播放需要分别对照。

**推动实现。** 使用睡前提醒、回家问候和普通问答比较不同方案；固定认可的声音参考，核对手机与音箱的播放差异，保留 24 kHz 音频并接入增量播放。对出现变调或截尾的片段回到生成与传输环节定位。

**验收。** 新语音通过实体音箱播放，用户确认自然连贯、结尾完整。专属语音素材与具体配置作为私有资产维护。

这项设计展示了将主观感受转化为实验变量、比较方案和选择标准的能力。

## 案例三 从口头答应到闹钟真正响起

**问题。** 用户谈论闹钟不一定要设置闹钟；一句「已经设好」也不能证明设备已接收任务。同时，对明确时间反复确认会让简单操作显得繁琐。

**产品判断。** 任务应根据真实意图和完整参数执行；完成反馈需要设备结果作为依据。已明确的普通单次闹钟指令直接处理。

**推动实现。** 区分交流与任务请求，组织结构化闹钟参数，将任务发送给实体设备并接收回执；同时关注用户在一段话中表达的交流内容。

**验收。** 自然语言下发闹钟后，设备到点实际响铃，按下表盘后停止，并回传停止状态。

这项设计展示了意图识别、工具执行、反馈与设备验收组成的完整产品流程。

## 怎样安排性能优化

将「用户说完到听见第一声」拆成收音结束、识别、上下文与回复、复核、语音准备、传输与开播，逐段测量。优先处理占主要等待的环节，再观察整体体验是否改善。

单机本地运行是本阶段的产品选择，因此优化同时考虑识别质量、声音自然度与模型资源安排。已经推进同模型识别加速、流式音频和模型资源交接；下一步继续针对整轮等待验证收益。
